## โครงสร้างข้อมูล

```
users                     คนที่ใช้ระบบ · document id = uid จาก Firebase Auth
products                  ประเภทที่เลือกได้ — รายการยา
requests                  โฟลเดอร์หลัก — คำขอหายา
  ├── identity/buyer      โฟลเดอร์ย่อย — ชื่อร้าน ล็อกทั้งใบ เปิดให้เฉพาะเจ้าของกับผู้แทนที่กดรับ
  ├── replies             โฟลเดอร์ย่อย — คำตอบของผู้แทนในคำขอใบนั้น
  └── aiLog               โฟลเดอร์ย่อย — บันทึกทุกครั้งที่ผู้ช่วย AI ระดับ 2 ทำงาน
```

ช่องที่จดชื่อซ้ำไว้ไม่ต้อง JOIN: `productName`
ชื่อร้านไม่ได้อยู่บนเอกสารคำขอ — อยู่ใน `requests/{id}/identity/buyer` ที่ล็อกทั้งใบ (PDPA)
ช่องบอกว่ารายการนี้เป็นของใคร: `buyerId` = uid ของคนที่ล็อกอิน
สถานะ: `รอผู้แทนรับ` → `รับแล้ว` / `ปฏิเสธ` — ผู้แทนเป็นคนกดเปลี่ยน

## ผู้ช่วย AI

| ระดับ | อยู่หน้าไหน | ใครกด | ทำอะไร |
|---|---|---|---|
| 1 | `new.html` | ร้านยา / คลินิก | อ่านช่องรายละเอียด แล้วเสนอรายการยาที่ตรงที่สุด (จากรายการที่มีจริงเท่านั้น) + ความเร่งด่วน |
| 2 | `detail.html` | ผู้แทนยา | ไปอ่านเอง 4 ที่ — คำขอใบนี้ · `products` · `replies` · คำขอรายการเดียวกันที่ยังรออยู่ — แล้วสรุปให้อ่านก่อนตัดสินใจ |

ช่องที่ใช้เก็บผลของ AI (ในเอกสาร `requests/{id}`)
- `aiSuggestion` — สรุปคำขอ · `aiReason` — สิ่งที่ควรดูก่อนตัดสินใจ · `aiUpdatedAt` — เวลาที่สรุป
- `requests/{id}/aiLog` — บันทึก `input` · `output` · `steps` · `model` · `byUid` · `createdAt` ทุกครั้งที่กด

กติกาที่บังคับไว้ทั้ง 2 ระดับ: มีสัญญาณกำลังทำงานและกดซ้ำไม่ได้ · มีป้าย "ข้อเสนอจาก AI — โปรดตรวจสอบก่อนยืนยัน" ·
AI ไม่ส่งคำขอและไม่เปลี่ยนสถานะเอง คนกดยืนยันเสมอ · รอเกิน 15 วินาทีหรือเรียกไม่สำเร็จ ขึ้นข้อความแล้วใช้งานต่อได้ตามปกติ
AI ไม่ได้รับชื่อร้าน (ส่งแค่เขต) และถูกสั่งห้ามให้คะแนน / จัดอันดับ / พูดเรื่องราคา ตามข้อห้ามใน `CLAUDE.md`

โมเดล `google/gemini-2.5-flash-lite` ผ่าน OpenRouter · คีย์ของหลักสูตรอยู่ใน `app/ai-config.js` ซึ่ง `.gitignore` กันไว้ ไม่มีใน repo

```bash
cp app/ai-config.example.js app/ai-config.js   # แล้วใส่คีย์ของหลักสูตร
```

ข้อจำกัดที่รู้อยู่แล้ว: คีย์ถูกส่งไปกับหน้าเว็บ เปิด F12 ก็เห็น — ยอมรับได้เฉพาะในหลักสูตรเพราะคีย์มีวงเงิน
Backlog Sprint 2: ย้ายการเรียก AI ไปไว้ฝั่งที่ผู้ใช้แตะไม่ได้

## ทีม AI ที่ใช้สร้างระบบนี้

ไฟล์ตั้งค่าอยู่ใน [`.claude/agents/`](.claude/agents) — แยกเป็น 3 ตัว คนละหน้าที่ คนละรุ่น
เพราะงานคนละแบบใช้กำลังคิดไม่เท่ากัน และรุ่นที่ใหญ่กว่าคิดค่าโทเคนแพงกว่า

| agent | หน้าที่ | รุ่น | ทำไมรุ่นนี้ |
|---|---|---|---|
| [`coder`](.claude/agents/coder.md) | เขียนโค้ดแอปจากสเปก · แก้ `app/` `*.html` `firestore.rules` | `opus` | งานหนักที่สุดและพลาดแล้วแพงที่สุด ต้องถือข้อห้าม 7 ข้อกับกับดัก 8 ข้อไว้พร้อมกันตอนเขียน |
| [`spec-reviewer`](.claude/agents/spec-reviewer.md) | อ่านโค้ดเทียบสเปกทีละช่อง จับฟีเจอร์ที่ไม่มีใครสั่ง | `haiku` | งานไล่เช็กลิสต์และ grep หาชื่อช่อง ไม่ต้องออกแบบอะไร รุ่นเล็กพอและถูกที่สุด |
| [`tester`](.claude/agents/tester.md) | เปิดเบราว์เซอร์จริงผ่าน Playwright MCP · เขียน `test-results.md` | `sonnet` | ต้องตัดสินจากสิ่งที่เห็นบนจอ แต่ไม่ต้องออกแบบระบบ รุ่นกลางคุ้มที่สุด |

กติกาที่บังคับไว้ในไฟล์ตั้งค่าทั้งสามตัว

- `coder` **ห้ามแตะ `tests/`** — คนเขียนโค้ดไม่ใช่คนตัดสินว่าโค้ดตัวเองผ่าน
- `spec-reviewer` **ไม่มีเครื่องมือเขียนไฟล์เลย** — คนตรวจที่แก้ของที่ตัวเองตรวจ เท่ากับลบหลักฐานทิ้ง
- `tester` **ห้ามแก้โค้ดแอปเพื่อให้เทสผ่าน** และห้ามแก้ผลย้อนหลัง เทสไม่ผ่านต้องรายงานว่าไม่ผ่าน

## รันในเครื่อง

ไม่มีขั้นตอน build ไม่มี npm — แต่เปิดไฟล์ตรง ๆ ด้วย `file://` ไม่ได้ เพราะหน้าเว็บใช้ ES module

```bash
cd nima-link-mvp
python3 -m http.server 8000
```

เปิด <http://localhost:8000/> — ยังไม่ล็อกอินจะเด้งไปหน้าเข้าสู่ระบบ

## Deploy

```bash
npx firebase-tools deploy --only hosting,firestore:rules
```

ห้าม deploy เว็บโดยไม่ deploy กฎไปพร้อมกัน

## หมายเหตุ

- `apiKey` ฝั่งเว็บไม่ใช่ความลับ จึง commit ขึ้น repo ได้ — ที่เป็นความลับคือ service account key ซึ่งโปรเจกต์นี้ไม่ได้ใช้และถูก `.gitignore` ไว้แล้ว
- Firestore **Test mode หมดอายุ 30 วันแบบเงียบ ๆ** ถ้าอยู่ ๆ อ่านข้อมูลไม่ได้โดยไม่ได้แตะอะไร ให้ดูตรงนี้ก่อน
- ข้อมูลตัวอย่างเป็น **ชื่อสมมติทั้งหมด** — แม้กฎฝั่งฐานข้อมูลจะกันข้ามร้านและข้ามช่องทางแล้วตั้งแต่สัปดาห์ที่ 8 ก็ยังไม่ใส่ข้อมูลจริงของคนอื่น เพราะนี่เป็นงานเรียนที่ repo เปิดสาธารณะ
- กฎความปลอดภัยไม่ได้มีแค่ "ต้องล็อกอินก่อน" อีกต่อไป — `firestore.rules` กันร้านอ่านคำขอของร้านอื่น กันผู้แทนข้ามช่องทาง OTC/MC ห้ามร้านเปลี่ยนสถานะของตัวเอง และซ่อนชื่อร้านไว้ใน `requests/{id}/identity/buyer` จนกว่าผู้แทน "คนที่กดรับใบนั้น" จะกดรับ
