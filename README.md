# NIMA Link — MVP (ADT-RAISE Batch 2 · Module 2)

ส่วนหนึ่งของโครงงาน **NIMA Link** — แอปเชื่อมร้านขายยา / คลินิก / โรงพยาบาล กับผู้แทนยา
repo นี้คือขอบเขตที่หยิบมาทำใน Module 2 เท่านั้น: **คำขอหายา (match request)**

ขอบเขตเต็มและเหตุผลที่เลือกส่วนนี้อยู่ใน [`SCOPE.md`](SCOPE.md)

---

## สถานะ — การบ้านที่ 1 (สัปดาห์ที่ 6)

| ส่วน | ทำอะไร | สถานะ |
|---|---|---|
| A | เอา prototype ขึ้น GitHub | เสร็จ |
| B | ออกแบบโครงสร้างข้อมูล | เสร็จ — ดู `SCOPE.md` |
| C | สร้าง Firestore + ใส่ข้อมูลตัวอย่าง | `seed.html` |
| D | หน้ารายการอ่านจากฐานจริง | `index.html` |

ยังไม่ทำงานของสัปดาห์ที่ 7 (เพิ่ม/แก้/ลบ) และสัปดาห์ที่ 8 (security rules + ผู้ช่วย AI)

## โครงสร้างข้อมูล

```
products                  ประเภทที่เลือกได้ — รายการยา
users                     คนที่ใช้ระบบ — ร้าน/คลินิก กับ ผู้แทน
requests                  โฟลเดอร์หลัก — คำขอหายา
  └── replies             โฟลเดอร์ย่อย — คำตอบของผู้แทนในคำขอใบนั้น
```

ช่องที่ **จดชื่อซ้ำ** ไว้ใน `requests` เพื่อไม่ต้อง JOIN: `buyerName` · `productName`
ช่องบอกว่ารายการนี้เป็นของใคร: `buyerId`
สถานะ: `รอผู้แทนรับ` → `รับแล้ว` / `ปฏิเสธ` — ผู้แทนเป็นคนกดเปลี่ยน

## วิธีรัน

ไม่มีขั้นตอน build ไม่มี npm — แต่เปิดไฟล์ตรง ๆ ด้วย `file://` ไม่ได้
เพราะหน้าเว็บใช้ ES module ซึ่งเบราว์เซอร์บล็อกบน `file://`

```bash
cd nima-link-mvp
python3 -m http.server 8000
```

1. วาง `firebaseConfig` จาก Firebase Console ลงใน `app/firebase-config.js`
2. เปิด <http://localhost:8000/seed.html> แล้วกดปุ่ม — ใส่ข้อมูลตัวอย่าง
3. เปิด <http://localhost:8000/> — หน้ารายการอ่านสดจาก Firestore
4. ลองแก้ข้อมูลใน Firebase Console แล้วกด F5 หน้าเว็บต้องเปลี่ยนตาม

## หมายเหตุ

- SDK เรียกจาก CDN gstatic **ตรึงเวอร์ชันไว้ที่ 12.18.0** ไม่ใช่ `import from "firebase/app"` ซึ่งต้องมี bundler
- `apiKey` ฝั่งเว็บไม่ใช่ความลับ จึง commit ขึ้น repo ได้ — ที่เป็นความลับคือ service account key ซึ่งโปรเจกต์นี้ไม่ได้ใช้
- Firestore **Test mode หมดอายุ 30 วันแบบเงียบ ๆ** ถ้าอยู่ ๆ เว็บอ่านข้อมูลไม่ได้โดยไม่ได้แตะอะไร ให้ดูตรงนี้ก่อน
- ข้อมูลตัวอย่างเป็น **ชื่อสมมติทั้งหมด** ไม่มีข้อมูลจริงของบุคคลอื่น
