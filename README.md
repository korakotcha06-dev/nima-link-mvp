## โครงสร้างข้อมูล

```
users                     คนที่ใช้ระบบ · document id = uid จาก Firebase Auth
products                  ประเภทที่เลือกได้ — รายการยา
requests                  โฟลเดอร์หลัก — คำขอหายา
  └── replies             โฟลเดอร์ย่อย — คำตอบของผู้แทนในคำขอใบนั้น
```

ช่องที่จดชื่อซ้ำไว้ไม่ต้อง JOIN: `buyerName` · `productName`
ช่องบอกว่ารายการนี้เป็นของใคร: `buyerId` = uid ของคนที่ล็อกอิน
สถานะ: `รอผู้แทนรับ` → `รับแล้ว` / `ปฏิเสธ` — ผู้แทนเป็นคนกดเปลี่ยน

## รันในเครื่อง

ไม่มีขั้นตอน build ไม่มี npm — แต่เปิดไฟล์ตรง ๆ ด้วย `file://` ไม่ได้ เพราะหน้าเว็บใช้ ES module

```bash
cd nima-link-mvp
python3 -m http.server 8000
```

เปิด <http://localhost:8000/> — ยังไม่ล็อกอินจะเด้งไปหน้าเข้าสู่ระบบ

## Deploy

```bash
npx firebase-tools deploy --only hosting,firestore:rules
```

ห้าม deploy เว็บโดยไม่ deploy กฎไปพร้อมกัน

## หมายเหตุ

- `apiKey` ฝั่งเว็บไม่ใช่ความลับ จึง commit ขึ้น repo ได้ — ที่เป็นความลับคือ service account key ซึ่งโปรเจกต์นี้ไม่ได้ใช้และถูก `.gitignore` ไว้แล้ว
- Firestore **Test mode หมดอายุ 30 วันแบบเงียบ ๆ** ถ้าอยู่ ๆ อ่านข้อมูลไม่ได้โดยไม่ได้แตะอะไร ให้ดูตรงนี้ก่อน
- ข้อมูลตัวอย่างเป็น **ชื่อสมมติทั้งหมด** — กฎฝั่งฐานข้อมูลตอนนี้มีแค่ "ต้องล็อกอินก่อน" ยังไม่กันข้ามร้าน จึงห้ามใส่ข้อมูลจริงของคนอื่นจนกว่าจะจบสัปดาห์ที่ 8
